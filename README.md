# ペリカカジノ（Discord ミニゲーム Bot）

ゲーム内の仮想通貨「**ペリカ**」で遊ぶ、友達向けのお遊びカジノです。
**現実のお金とは一切関係なく、換金もできません。** 課金や購入の仕組みもありません。

**ペリカは「サーバーごと」に別々です。** 残高・デイリー・ショップの景品・成績・履歴は、サーバーごとに独立していて、別のサーバーには持ち込めません（初めて遊ぶサーバーでは、そこで3,000ペリカから始まります）。

## 遊び方

各サーバーで初めて遊ぶとき、**3,000ペリカ** がもらえます。賭け金は **10ペリカ以上（上限なし。残高が上限）**。同時に遊べるゲームは1つだけです。
ペリカが尽きても、`/ペリカ デイリー` で6時間ごとにもらえます。

### チンチロのルール
サイコロ3個を振って役で勝負します。親（ディーラー）が先に振り、そのあとあなたがボタンで振ります。

| 役 | 内容 | 勝ったときの倍率 |
|---|---|---|
| ピンゾロ | 1-1-1 | 5倍 |
| 嵐（アラシ） | 2〜6のゾロ目 | 3倍 |
| シゴロ | 4-5-6 | 2倍 |
| 目 | ペア＋1つ。残った1つが目の数（6が最強） | 1倍 |
| 目なし | 役なし。3回まで振り直せる | — |
| ヒフミ | 1-2-3。**負け役**で、負けると相手の役の倍率が**さらに2倍**（例: シゴロ対ヒフミは4倍） | — |

- 強さは「ピンゾロ ＞ 嵐 ＞ シゴロ ＞ 目 ＞ 目なし ＞ ヒフミ」。同じ強さは引き分け（賭け金が戻る）。
- 負けたとき、相手の役が嵐・ピンゾロなら 3倍・5倍払い（ヒフミで負けるとその2倍で、最大10倍）。賭け金のほかに払う分は、まず残高から引かれ、足りない分は強制執行（下の「借金と身分」）のあと、**帝愛への借金**になります。
- 借金は、**収入（ゲームの純利益・デイリー・ミッション報酬・受け取った送金など）の3割が天引き**されて返ります。借金がある間は、ショップの購入・証券の購入・送金・クイズの出題はできません。ランキングの総資産は借金を引いた額です。くわしくは「借金と身分」の節。
- **目なし同士は親の勝ち**です（これが胴元の取り分）。

結果の乱数は OS の乱数（`SystemRandom`）で、予測や再現はできません。払い戻しの端数（1.95倍や0.3倍など）は切り捨てです。

## 証券の銘柄と相関

| 銘柄 | 値動きの大きさ（1分） | 性格 |
|---|---|---|
| 🪙 CSトークン | 0.4% | 標準。ほかの銘柄の基準 |
| 🏭 TEIO重工 | 0.35% | CSと強い正相関（+0.85）。GOLDとは逆（−0.5） |
| 🧪 NUMAバイオ | 1.2% | 超高ボラの仕手株。ほかとはほぼ無相関（+0.05） |
| 🥇 GOLD地金 | 0.2% | CSと逆相関（−0.6）の避難先 |

- 乱数は、分散共分散行列 Σ（σᵢσⱼρᵢⱼ）のコレスキー分解で相関をつけ、`P ← P·exp(−Σᵢᵢ/2 + 揺れ)` と動かします。この補正で、**どの銘柄も期待値はちょうど変わりません**（先を読んで儲けることはできません）。
- 約1日に2回、**有事**（全銘柄が同じ向きに急騰・急落）が起こります。CSで±3〜8%、ほかの銘柄は値動きの大きさの比（最大2倍）をかけた分だけ動きます。有事には逆相関のヘッジが効かなくなります。
- `/証券 価格` と `/証券 チャート` に、直近24時間の実測の相関が出ます。
- 旧版の `/暗号`・`/債券` は `/証券`・`/証券 債券` に統合しました。以前のCSトークンの保有・空売り・履歴は、そのままCSトークンとして引き継がれます。
- 銘柄をまたぐ担保・信用買い・口座維持率は、次の段階で足す予定です（issue #2）。

## 空売り

価格が**下がると儲かる**賭けです。`/証券 空売り` で、銘柄・枚数（または金額）とレバレッジ（1・2・3・5倍）を選びます。

- 預ける**担保 = 売り建てた総額 ÷ レバレッジ**です。残高から預かります。
- 閉じるときは `/証券 買い戻し` で、銘柄と枚数か割合（半分・全部）を選びます。戻る額は「担保 + 損益」で、0より下にはなりません。
- 損失が**担保の50%**に達すると、1分ごとの価格更新のときに**強制決済（ロスカット）**されます。レバレッジが大きいほど、小さな値上がりでロスカットされます（5倍なら+10%、1倍なら+50%）。
- 建玉は、1人につき銘柄ごとに1つです。追加で建てると、平均の建値でまとめられます。ロスカットは、銘柄ごとに自分の価格で判定します。借金があるときは建てられません。
- 手数料も金利もありません。価格の決まり方は現物と同じで、期待値は変わりません（必勝法はありません）。
- ランキングの総資産には、担保と含み損益が入ります。

## 突発イベント

1日に1回、**日本時間の12時〜23:30のどこか**で、**1つのゲームだけ30分間**、勝ったときの勝ち分（払い戻し − 賭け金）が**1.5倍**になります。上乗せは1回につき最大10,000ペリカです。

- どのゲームで、何時に始まるかは、日付とサーバーごとに決まります（運営の設定は不要）。
- 開始と終了は、ランキング掲示のチャンネル（無ければサーバーのシステムチャンネル）に自動で投稿されます。メンションは付きません。
- Bot が止まっていて開始を逃した日は、告知もイベントも行いません（終了後に起動しても何も投稿しません）。
- 負けたときや引き分けには、何も付きません。

## クイズ（時事ネタ・豆知識で稼ぐ）

`/クイズ 挑戦` で、まだ答えていない問題が1問ずつ、自分だけに見える形で出ます。4択のボタンで答え、**正解すると問題ごとの報酬**（既定100ペリカ）がもらえます。

- 1問につき**1人1回だけ**です。不正解でもやり直せません。答えたあとに、正解と解説が出ます
- 公開された問題に誰かが答えると、その場で「⭕ 〇〇が正解！」「❌ 〇〇が不正解…」が**みんなに見える形で**出ます（選んだ答えと正解は出しません。解説つきの結果は本人だけに見えます）
- 選択肢の並びは、問題を登録するときに1回だけシャッフルして固定します（誰が見ても同じ並びです）
- 登録すると、**全サーバーの告知チャンネル**（ランキング掲示のチャンネル、無ければシステムチャンネル）に、問題文と A〜D のボタンが投稿されます。**その場でボタンを押して答えられます**（結果は本人だけに見えます）。再起動しても、押せます
- 問題は全サーバー共通です。報酬は、答えたサーバーの口座に入ります（借金があれば、収入の3割が天引きされます）
- 持ち主の問題の報酬はシステムが払います。稼げる量は、問題の数で決まります（回答数の上限は別にありません）
- ミッション・連勝・週間ランキング・突発イベントには数えません

**みんなが出題する（`/クイズ 出題`）**

誰でも自分の問題を出せます。入力フォームに、問題文・選択肢（4行。1行目が正解）・解説・「報酬 / 期間」（例: `100 / 2日`。期間は省略可）・「正解・不正解の文言」（省略可）を入れます。
- **正解・不正解の文言**: 2行で、1行目が正解のとき、2行目が不正解のときの見出しの言葉です（各20文字まで）。「⭕ 正解！」「❌ 不正解…」の「正解！」「不正解…」の部分が、結果の画面とみんなに見える通知で差し替わります。省略した方は、今までどおり「正解！」「不正解…」です（片方だけも書けます）

- 問題には、**制作者の名前**（登録したときの表示名。持ち主の問題も同じ）が「出題: 〇〇」と出ます
- 問題は、出したチャンネルに投稿され、ボタンで答えられます。**そのサーバーの中だけ**に出ます（ペリカがサーバーごとの口座なので）
- 正解1人への報酬（**1ペリカ以上。上限なし**）は、**出題者本人のペリカから払われます**。払うたびに出題者の残高から引き、**残高が足りなくなったら、足りない分は出題者の借金**になります（回答者には報酬を全額払い、公開メッセージに「⚠️ 出題者の残高が足りないため…借金になりました」と出ます）。借金は、出題者に入るお金から先に自動で返済され、返し終わるまで、出題と送金ができません。借金の上限はありません
- **正解の報酬をもらえるのは、ゲームを3回以上遊んだ人だけ**です（複数アカウントでペリカを作るのを防ぐ、送金と同じ条件）。3回未満の人も正解にはなりますが、報酬はなく、出題者は払いません。出題者の受け取り（下）にも数えません。持ち主の問題には、この条件はありません
- **出題者は自分の問題に答えられません**。有効な期間は1分〜7日（「90分」「6時間」「2日」の形。空欄なら3日）で、正解者数の上限はありません
- **回答者が2人以上**になると、出題者にシステムから次の3つが入ります（2人に満たないと、出題報酬はありません）。**回答のたびに**、その時点の合計との差が**その場で**払われ、公開メッセージに「💰 出題者 +〇〇（累計 〇〇）」と出ます。正答率が40%から離れると合計が下がり、その差額は出題者の残高から戻されます（残高の範囲まで）。期限・取り下げのときは、最終結果をまとめて出します
  - **基本報酬** 100ペリカ × 倍率
  - **正答率ボーナス** 最大200ペリカ × 倍率
  - **参加報酬** 回答者1人につき「報酬」ぶん（報酬 × 回答者数）。上限なし。人気の問題ほど増えます
  - **倍率** は、報酬が高いほど基本とボーナスを増やします（√(報酬÷100)。報酬100で×1、400で×2、1000で約×3.2。25なら×0.5）
  - ボーナスと参加報酬には、正答率が**40%**に近いほど大きくなる係数がかかります（ちょうど40%で満額、そこから離れるほど減り、0%と80%以上では0）。誰も解けない問題や簡単すぎる問題では稼げません
  - 例（報酬100・回答10人）: 正答率40% → 支払い400、受け取り1,300（100＋200＋1,000）で **+900**。20% → +500。60% → +100。70% → −300（簡単すぎて正答率が上がると赤字）
  - 例（報酬1,000・回答10人・正答率40%）: 支払い4,000、受け取り316＋632＋10,000＝10,948で **+6,948**。報酬を上げるほど、黒字（と赤字）の幅が広がる「ハイリスク・ハイリターン」です
  - 正解者への報酬は、出題者の残高から払われます。報酬が高い問題は、出題者の残高が尽きると借金になります
- 結果（参加人数・正答率・出題報酬と、**正解者・不正解者の一覧**）は、問題を投稿したチャンネルに、出題者へのメンションつきで出ます
- 乱用を防ぐため、1人が**同時に出せるのは2問まで、24時間に3問まで**です。借金中は出題できません
- 不適切な問題は、持ち主が `/運営 クイズ 削除` で消せます（出題報酬は出ません）
- 数字は `core/quizpay.py` で調整できます

**一括登録のファイルの書き方**（問題は `---` だけの行で区切ります。`#` で始まる行はメモです）

```
問題: 2026年に開かれる〇〇は？
正解: 正しい選択肢
不正解: まちがいの選択肢1
不正解: まちがいの選択肢2
不正解: まちがいの選択肢3
解説: 解説（なくてもよい。次の行に続けて書けます）
報酬: 100        ← なくてもよい（既定100。1以上。上限なし）
期間: 2時間      ← なくてもよい（なければ無期限。「90分」「2時間」「1時間30分」「3日」の形。1分〜365日）
                      「時間: 2」「日数: 3」「分: 90」と、単位を見出しにして数字だけ書いてもよい
---
問題: 次の問題…
```

**問題の登録（Bot の持ち主だけ）**

| コマンド | 内容 |
|---|---|
| `/運営 クイズ 追加` | 入力フォームが開きます。「告知」を「しない」にすると、告知を出さず `/クイズ 挑戦` だけに出ます（まとめて登録するとき用）。問題文・選択肢（4行。**1行目が正解**）・解説・「報酬 / 期間」（報酬は1以上（上限なし）、期間は「90分」「2時間」「3日」の形。例: `100 / 3日`。期間を省くと無期限）・「正解・不正解の文言」（2行。省略可）を入れます |
| `/運営 クイズ 一括追加` | 問題を書いた**テキストファイル（.txt、UTF-8）を添付**して、まとめて登録します。送ると一覧のプレビューが出て、「登録する」を押すまで登録しません。1つでも誤りがあると**1問も登録せず**、何問目のどこが誤りかを返します。すでに登録済みの問題文は、重複として断ります（同じファイルを2回送っても二重になりません）。`告知` を「する」にすると、全サーバーに1問ずつ出します（既定は「しない」）。一度に30問まで |
| `/運営 クイズ 一覧` | 登録した問題（新しい順に15件）。正解・報酬・期限・正解した人数が出ます |
| `/運営 クイズ 削除` | 番号を指定して削除します（回答の記録も消えます） |

時事ネタは、有効な期間を入れておくと、古くなった問題が自動で出なくなります。分や時間の単位でも指定できます。

## 債券（通常債とジャンク債）

`/証券 債券 買う` で種類と金額（1,000ペリカ以上）を選ぶと、元本を先に預かります。満期になると、**自動で残高に入ります**（`/証券 債券 保有` を開いたときにも反映します）。

| 種類 | 期間 | 利息 | 倒産 | 解約 | 元本の上限（合計） |
|---|---|---|---|---|---|
| 🏦 通常債 | 3日 | +4% | なし（元本保証） | できる（元本の10%引き） | 30,000 |
| 🗑️ ジャンク債 | 1日 | +20% | **20%の確率**（元本が戻らない） | できない | 10,000 |

- 倒産するかどうかは、満期のときに抽選します。ジャンク債の期待値は約96%（(1−0.20)×1.20）で、運のゲームとして遊ぶ形です
- 借金があるときは買えません。預けている元本は、ランキングの総資産に含まれます
- `/証券 債券 保有` に、持っている債券（`#番号`・満期・受取額）と、最近の決着（満期・倒産・解約）が出ます。決着の通知は出ません
- ミッション・連勝・週間ランキング・突発イベントには数えません
- 利率・期間・上限は `core/bonds.py` の数字を書き換えて調整します

## 抽選（持ち主が開催）

Bot の持ち主（`owner_ids`）が、Bot とのDMで `/運営 抽選 開催` を使って始めます。参加費は500以上（上限なし）で指定するか、省略すると500〜3,000のランダムです。募集時間は分で指定します（省略で60分）。

- 参加は、投稿の「🎟️ 参加する」ボタンです。**参加費は押した時点で先に引かれ**、全員同じ額です。借金があるときは参加できません
- 締切に、参加者から1人を等確率で選びます。当選者が、集めた参加費の**全額**を受け取ります（手数料なし）
- 参加者が2人に満たないとき、`/運営 抽選 中止` したときは、全員に全額を返します
- 投稿がコメントで流れたら、`/運営 抽選 再掲示` で告知チャンネルに出し直せます（古い投稿は消え、参加者はそのままです）
- 募集中は1サーバーに1つだけです。開催状況と参加者は保存され、Bot を再起動しても続きます（締切を過ぎていれば、起動後に結果を出します）
- 参加費を預けている間は、ランキングの総資産がその分だけ減って見えます
- ミッション・連勝・週間ランキング・突発イベントには数えません

## ペリカのお金の流れ

運営口座の仕組みは廃止しました（ユーザーが負けた分・勝った分は、どこにも記録されません）。デイリー・ミッション・初期支給は、そのまま残高が増えます。
- ペリカはゲーム内の数字で、現実のお金とは無関係です。現実のお金に換える、売る、買うといった使い方はできません

## 借金と身分（帝愛ファイナンス）
借金は、**帝愛ファイナンスからの借金**です（プレイヤー同士の `/貸付` とは別）。数字は `core/teiai.py` で調整できます。

- **強制執行**: チンチロの倍払いなどで払えないとき、**現金 → 空売り → 証券（現物・全銘柄）→ 通常債（古い順）**の順に差し押さえて充て、それでも足りない分が借金になります。現金で足りれば、証券には手を付けません。結果の画面に、差し押さえたものが出ます。
- **種銭**: 借金があって手元が空になると、帝愛が**種銭 3,000ペリカ**を貸し付けます（借金に加わります）。「これで取り返してこい…！」
- **天引き**: 収入の**3割**が、借金の返済に天引きされ、残りは手元に残ります。ゲームは、賭け金は全額戻り、**純利益の3割だけ**です（負けや引き分けからは引きません）。デイリー・ミッション報酬・クイズの報酬・抽選の当選・受け取った送金・債券の利息も収入です。管理者の付与・借りたお金・賭け金の返金・証券や債券の売却は、収入ではありません。
- **デイリーのピンハネ**: 借金中は、デイリーの**2割を帝愛が没収**します（借金の元本は減りません）。残りの3割が天引きされ、手元が種銭の枠（3,000）に満たなければ、枠まで貸し付けます。
- **返済**: `/ペリカ 返済` で、手元のペリカから、いつでも返せます（金額を省くと、返せる限り全額）。
- **身分**（`/ペリカ 残高` に出ます）: 🟢 **カタギ**（借金も延滞もない）／🟡 **地下労働者**（帝愛の借金か、貸付の延滞がある）／🔴 **破産者**（自己破産のあと、完済して7日たつまで）。
  - カタギから落ちた瞬間に、**連続ログインは0に戻ります**。
  - 地下労働者・破産者の間は、買った**称号・カードの色とアイコン・演出の変更品・コレクションが差し押さえ中**で、見えません（記録は残り、カタギに戻ると使えます）。残高カードには「🔒 差し押さえ中」と出ます。
  - **ニックネームの末尾に、`【地下労働者】` `【破産者】` が自動で付きます**（2分おきに確認。称号の表示を選んでいなくても付きます）。完済してカタギに戻ると、元のニックネームに戻ります。サーバーの持ち主・Bot より上のロールの人・Bot に「ニックネームの管理」権限がないサーバーでは、付けられません。ランキングでは、名前の横に 🟡 🔴 が付きます。
- **借金中の `/貸付`**: 帝愛の借金があっても、借りられます（借り換え）。回収の順番は、**帝愛 → 延滞中の `/貸付`（古い順）**です。借金中の送金・クイズの出題は、これまでどおりできません。
- **自己破産**（`/ペリカ 破産`。確認ボタンのあとに実行。**元に戻せません**）:
  1. **全財産（現金・空売り・証券・債券）と、ショップの全品（称号・カード・演出・コレクション・消耗品）を差し押さえ**ます。解約できないジャンク債と、ショップの品は、購入額（元本）の**50%**で換金します。
  2. 換金した合計を、**帝愛 → 貸付（古い順）**の順に配当します。あまれば、手元に残ります。
  3. **貸付の残りは免責**（貸した人の損）。**帝愛の借金は、残っていても10,000ペリカまで圧縮**されます（完全には消えません）。
  4. 身分が🔴**破産者**になり、**完済して7日たつまで、貸付を借りられません**。
  - 借金も貸付の借り入れもないと、破産できません。破産のあと、手元が空で借金が残るなら、種銭が貸し付けられます。
- 本番には、すでに借金がある人がいますが、そのまま帝愛の借金として扱います（次の収入から、新しい天引きに変わります）。

## 貸し借り（ユーザー同士）

`/貸付 提案` で、相手・金額・**日利**・期間を決めて、貸す提案を出します。投稿の「承諾」を**借りる本人**が押すと成立し、お金が移ります（承諾の期限は24時間）。

- 金額は100ペリカ以上、日利は0%以上（0.1%刻み）で、**どちらも上限はありません**（貸す人の残高が足りること、借りる人が承諾することが歯止めです）。期間は1〜30日です
- **利息は日割りの単利**です。利息 ＝ 元本 × 日利 × 経過日数（貸した時刻から数えて切り上げ、最低1日、期間が上限）。早く返せば、利息は減ります。期限を過ぎても、延滞の利息は付きません
- 返済は `/貸付 返済`（金額を省くと、残高の範囲で全額）。返済は、まず元本、次に利息に充てます
- 期限が来ると、**借りた人の残高から自動で回収**します。足りない分は**延滞**になり、借りた人の収入の3割の天引きから、帝愛の返済のあとで、古い順に自動で回収します
- 延滞があるとき、破産者のブラックリストの間は、新しく借りられません（帝愛の借金があるだけなら借りられます）。同時に貸せるのは10件まで、承諾待ちの提案は5件までです（借りる件数に上限はありません）。提案の画面には、借りる人の身分と、帝愛への借金が出ます
- 期限の前日と、延滞になったときに、提案を出したチャンネルに知らせます。`/貸付 一覧` で、自分の貸し借りを見られます
- 担保（証券・称号・債券）は、次の段階で足す予定です

## 還元率のレベル（持ち主が変える）

持ち主は、Bot とのDMで `/運営 還元率 設定`（サーバー・ゲーム〔または「すべて」〕・レベル）を使い、ゲームごとの還元率を **1〜6** の6段階で変えられます。**3が標準（いまの設定）**です。`/運営 還元率 一覧` で、いまのレベルと還元率の目安を見られます。

- **勝ったときの勝ち分だけ**を、一定の倍率で増減します。負け・引き分けは変わりません
- 1段階で、還元率が約**4ポイント**動きます（レベル1で約−8、レベル6で約+12）。ゲームごとに倍率を計算するので、どのゲームも同じ幅で動きます（ルーレットは賭け方ごとに計算します）
- 目安: スロット 88%〜108% ／ ルーレット（赤・黒など）89%〜109% ／ パチンコ 約92%〜112% ／ チンチロ 約90%〜110% ／ ブラックジャック 約84%〜104%（ブラックジャックとチンチロは、打ち方で変わる目安です）
- 設定はサーバーごとです。レベル4以上では、還元率が100%を超えるゲームがあり、遊ぶだけでペリカが増えます
- ユーザーには、レベルは見せません

## パチンコ（打ち出し型）

実機に近づけた作りです。**1セット = 100発**を打ち出し、賭け金がそのセットの代金です。

- 玉は1発ごとに、約**7%**がスタートに入ります（平均7回転/セット）。**入らない玉は、釘やハズレの穴に落ちます**。1回も入らないセットもあります
- 入った数だけ回転します。回転ごとに、予告の色（青<赤<金）とリーチの格（ノーマル<スーパー<プレミアム）が出て、**出るほど当たりやすく**なります。リーチなしで突然揃う「サプライズ当たり」もあります
- 当たると**大当たり**。出玉は賭け金の**2倍（69.5%）・10倍（26.5%）・30倍（4%）**のどれかで、**確変の連チャンが50%で続きます**（平均2連）。1セットの払い戻しは、出玉の合計です（**上限はありません**）
- 当たるセットは約**9%**。還元率は100%を超えないよう調整してあります
- **`回数`（1〜10）**で、同じ賭け金のセットを続けて打てます。賭け金 × 回数 が、そのまま賭け金になります（残高が足りないと始まりません）。結果の下の「🎰 ×5連続」（5セットのあとは「×10連続」）のボタンでも続けられます。連続して打っても、**1回の遊び**として数えます（ミッション・連勝・週間ランキングは1回分）
- 結果は賭けた時点で決まり、先に精算します。**当たった回転だけ**を、実機のように見せます。リールは「回っている／止まっている」の状態を持ち、左右が同じ絵柄で止まると**リーチ**、そのあと出目が決まるまで左右は変わりません（変わるのは、再回転する擬似連・全回転のときだけ）。**3つ揃うのは最後の1コマだけ**で、揃ったら演出は終わり、すぐ当たりの宣言になります。演出は、格（リーチなし・ノーマル・スーパー・プレミアム）ごとの台本から**1本を選んで**流し、予告・擬似連（0〜4回）・カットイン・発展の種類は回ごとに変わります（全部が毎回流れるわけではありません）。当たりの宣言と連チャンの演出（当たりの宣言と連チャン連チャン数の大表示・5連や10連の節目・終了のまとめ）は、演出が終わったあとに出します（ハズレの回転は「〇回転 経過」のように数字でまとめ、外れたリーチは文字で触れるだけです）。当たりが複数あっても省略せず、約60コマ（約66秒）分の上限まで順に見せ、超えた分は数でまとめます。連続投入でも、当たったセットを出玉の大きい順に、上限まで見せます
- 持ち主向けの `/運営 還元率` のレベルは、セットごとに勝ち分へかかります

## サーバーの承認（友達のサーバーだけで遊ぶ）
`config.json` に `"require_approval": true` と、自分のユーザーIDを入れた `owner_ids` を設定すると、**Bot が新しいサーバーに追加されたとき、持ち主に DM で通知が届きます**。

1. 友達が招待 URL から Bot を追加します。
2. 持ち主に DM が届きます（サーバー名・ID・持ち主・メンバー数つき）。ボタンは **【許可する】** と **【断って退出させる】** です。
3. 【許可する】を押すと、そのサーバーIDが記録に保存され、**再起動なしですぐ**遊べるようになります（サーバー側にも通知します）。
4. 承認前のサーバーでコマンドを使うと「承認待ちです」と表示され、持ち主にもう一度（1時間以上あけて）通知されます。

- **持ち主のコマンド**（`/運営`）: **Bot とのDMでだけ**使えます（サーバーのコマンド候補には出ません）。`/運営 サーバー一覧`（許可・承認待ち・断った一覧）、`/運営 サーバー許可 サーバーid`（IDを指定して許可。まだ参加していないサーバーを先に許可しておくこともできます）、`/運営 サーバー取消 サーバーid`（許可を取り消して、Bot を退出させる）。設定ファイル（`allowed_guild_ids`）で許可したサーバーは取り消せません。
- 持ち主は、承認待ちのサーバーの中でもコマンドを使えます（そこから許可を出せます）。
- DM を受け取れない設定の場合は、Bot とのDMで `/運営 サーバー一覧` を使って承認待ちを確認し、`/運営 サーバー許可` で許可してください。
- ボタンは Bot を再起動しても動きます。一度断ったサーバーは、追加し直すと、もう一度確認が届きます。

## ランキング掲示板（自動で更新）
`/ペリカ ランキング掲示 チャンネル:#ランキング` を一度実行すると、Bot がそのチャンネルにこのサーバーのランキング（上位10人）を投稿します。以降は **同じメッセージを1分ごとに書き換える** ので、新しい投稿は増えません。

- 設定できるのは「サーバー管理」権限を持つ人と Bot の持ち主（`owner_ids`）で、**1サーバーに1つ**です。もう一度実行すると、前の掲示板を削除して新しく置き直します。
- メッセージが消されても、次の更新で自動的に投稿し直します。チャンネルが消えたら、掲示は自動で止まります。
- 止めるときは `/ペリカ ランキング掲示` で「止める」を True にします（投稿も削除します）。Bot が再起動しても、掲示は続きます。
- Discord の仕様上、Bot が編集できるのは **Bot 自身が投稿したメッセージだけ** です（人が貼ったメッセージは編集できません）。
- 載るのは、そのサーバーで遊んだ・コマンドを使った人だけです。

### 称号をニックネームに付ける
「🎒 持ち物」の画面で「称号を名前の後ろに付ける」を押すと、装備中の称号が **ニックネームの後ろ** に付きます（例: `たつ【ざわ…ざわ…】`）。メッセージの名前の横に表示されます。

- **自分で選んだ人だけ**、そのサーバーでだけ有効です（初期は付けません）。「称号を名前に付けない」で、元のニックネームに戻ります。
- 称号を付け替えたり外したりすると、ニックネームも自動で変わります。ONにしている複数のサーバーにも反映されます。
- Bot に **「ニックネームの管理」権限** が必要です。**サーバーの持ち主と、Bot のロールより上のロールの人は、Discord の仕様で変えられません**（その場合は理由を案内して、設定は有効になりません）。
- ニックネームは32文字までなので、長い名前の人は、称号を残して名前の後ろが切れて付きます。**付ける前のニックネームは記録しているので、称号を外すと、切れる前の名前に完全に戻ります。**
- 自分でニックネームを変えると、称号が消えることがあります。もう一度「🎒 持ち物」の画面で付け直せます。自分で付けた `【…】` は消しません（ショップの称号と同じ名前のものだけを外します）。
- 一度も ON にしていない人のニックネームには、Bot は触りません。Bot がサーバーから外れると、そのサーバーの設定は消えます。

### 名前の色（ロール）について
- Bot が「ペリカ・赤」のようなロールを作って付けます。**権限は一切持たない、色だけのロール**です。同じ名前で権限を持つロールがすでにあるサーバーでは、安全のため使わず、名前を変えるよう案内します。Bot が付け外しするのは、この色ロールだけです。
- Bot に **「ロールの管理」権限** が必要です。招待URLの権限は `permissions=402738176` にしてください（すでに招待済みなら、そのURLをもう一度開いて承認すると権限が追加されます）。
- サーバーの名前の色は、**ロール一覧で一番上にある「色つきのロール」の色** になります（色が「デフォルト」のロールは無視されます）。
  色ロールは Bot のロールのすぐ下に置くので、それより上にある運営用ロールなどの色は優先されます。
  すでにある別のロール（例: シークレットチャンネル用）に色が付いていて、それが色ロールより上にある場合は、そちらの色が優先されます。色ロールを優先させたいときは、そのロールの色を「デフォルト」にするか、色ロールより下に動かしてください。
- Bot のロールは、色ロールを動かせるように、サーバー設定のロール一覧で十分上（運営用ロールの直下など）に置いてください。

## 導入手順

### 1. Discord 側の準備
1. [Discord Developer Portal](https://discord.com/developers/applications) で **「新しいアプリケーション」** を作ります。
2. **「Bot」** を開き、**「トークンをリセット」** でトークンをコピーします（一度しか表示されません。他人に見せないでください）。
3. **特権インテントは不要です**（メッセージの内容もメンバー一覧も読みません）。

### 2. 設定と起動

**uv を使う場合（推奨）:**
```bash
uv sync
cp config.example.json config.json      # Windows: copy config.example.json config.json
uv run main.py
```

**pip / venv を使う場合:**
```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp config.example.json config.json      # Windows: copy config.example.json config.json
.venv/bin/python main.py                # Windows: .venv\Scripts\python main.py
```
`config.json` を編集します。

| 項目 | 説明 |
|---|---|
| `token` | Bot トークン（必須） |
| `allowed_guild_ids` | あらかじめ許可するサーバーのID一覧。`require_approval` が false のときは、空 `[]` ならどのサーバーでも遊べ、空でなければこの中だけ遊べます |
| `require_approval` | `true` にすると**承認制**になります。許可リスト以外のサーバーは、持ち主が承認するまで使えません（下の「サーバーの承認」参照）。初期は `false` |
| `legacy_guild_id` | サーバーごとに分ける前の古い記録がある場合に、それを引き継ぐサーバーのID。省略すると `allowed_guild_ids` の先頭を使います。古い記録がないとき（新規）は不要です |
| `owner_ids` | Bot の持ち主のユーザーID。サーバーの承認の通知（DM）が届き、`/運営` のコマンドを使える人です（複数可） |
| `test_guild_id` | 開発用。指定するとそのサーバーだけにコマンドが即時反映されます。**本番では `null`**（別の場所の Bot が登録したコマンドと重複して、同じコマンドが2つ表示されます） |
| `utc_offset_hours` | デイリーの切り替わる時刻とミッションの日付の境目の時差。日本は `9`（日本時間の0・6・12・18時にデイリーが、0時にミッションが切り替わります） |

サーバーID・ユーザーIDは、Discord の「設定 → 詳細設定 → 開発者モード」をオンにして、右クリックの「IDをコピー」で取れます。

### 3. サーバーへ招待
`CLIENT_ID` を、Developer Portal の「一般情報」にあるアプリケーションIDに置き換えて開きます。

```
https://discord.com/oauth2/authorize?client_id=CLIENT_ID&scope=bot+applications.commands&permissions=402738176
```
必要な権限は「チャンネルを見る」「メッセージを送信」「埋め込みリンク」と、ショップ用の「ロールの管理」（名前の色）・「ニックネームの管理」（称号の表示）、`/運営 発言削除` 用の「メッセージ履歴を読む」です。ショップと発言削除を使わないなら `permissions=19456` で足ります。

## 仕組みと安全
- **賭け金は開始時に預かり**、結果が決まったら精算します（スロット・パチンコなどは、演出の前に精算するので、演出の途中でメッセージを消しても結果は変わりません）。残高の増減は1回の処理で行い、台帳（履歴）に記録します。
- 連打や同時操作でペリカが増減しないよう、同じ人は同時に1つのゲームしか始められません。
- **Bot が途中で止まった場合、預かっていた賭け金は次の起動時に全額返ります。**
- ボタンは賭けた本人だけが押せます。放置すると、チンチロは「目なし」、ブラックジャックは「スタンド」として自動で精算します。
- 保存するデータ: サーバーごとの、ユーザーID・残高・成績・増減の履歴・持ち物。メッセージの内容は読みません。保存先は `data/casino.db` です。

## 運用
- 常時動かす場合は、`systemd` などで自動起動・自動再起動にします（管理補助bot と同じ要領）。**同じトークンで2か所から起動しないでください。**
- データのバックアップは、Bot を止めてから `data/` をコピーします。
- トークンを漏らしたら、すぐ Developer Portal で再発行して `config.json` を差し替えてください。`config.json` と `data/` は `.gitignore` 済みです。

## 持ち主向けの管理（Bot とのDMで操作します）
管理者用のコマンドは、**Bot とのDM**だけに出る `/運営` にまとめてあります（サーバー内のコマンド候補には出ません）。説明が `[管理者]` で始まり、使えるのは **Bot の持ち主（`owner_ids`）だけ**です。ほかの人がDMで使っても「権限がありません」と返ります。サーバーが必要なコマンドでは、`サーバー` の欄に、Bot が参加しているサーバー名の候補が出ます。

**告知を出す先（サーバーとチャンネル）を指定できます。** `お知らせ`・`抽選 開催`・`抽選 再掲示`・`イベント 開始`・`クイズ 追加`・`クイズ 一括追加` には `チャンネル` の欄があり、先に `サーバー` を選ぶと、そのサーバーで **Bot が投稿できるチャンネル**（見る・送る・埋め込みリンクの権限がある所）の候補が出ます。省略すると、これまでどおり告知チャンネル（ランキング掲示のチャンネル、無ければシステムチャンネル）です。`チャンネル` だけを選ぶことはできません（`サーバー` も必要）。特別イベントは、終了の告知も開始と同じチャンネルに出ます。

| コマンド | 内容 |
|---|---|
| `/運営 付与` | サーバーと相手（名前の候補が出なければユーザーID、`<@…>` の形も可）、金額（1〜10,000,000）、理由を指定してペリカを付与します。相手がそのサーバーにいなければ付与しません |
| `/運営 発言削除` | `サーバー` と `チャンネル` を選ぶと、そのチャンネルにある **Bot 自身の発言を、すべて消します**（他の人の発言には触れません）。**確認のボタンを押すまで消さず、元に戻せません。** ランキング掲示板・チャートの自動更新・クイズや貸付や抽選の投稿（ボタン付き）も消えます。自分の発言は1件ずつしか消せないので、多いと数分かかります。Bot に「メッセージ履歴を読む」権限が要ります（なければ、案内が出て何も消しません）。15分を過ぎて画面が更新できなくなったときは、結果が DM に届きます |
| `/運営 お知らせ` | 指定した文字（改行できます）と画像を、Bot がお知らせとして告知チャンネルに出します。`サーバー` を空にすると、許可されている全サーバーに送ります。`見出し`（空なら「📢 お知らせ」）と `画像`（8MBまでの画像）は任意です。**送る前にプレビューが出て、「送信する」を押すまで送りません**。通知（メンション）は飛びません |
| `/運営 イベント 開始` `終了` | 好きなタイミングで**特別イベント**を開きます（突発イベントと同じ「勝ち分の上乗せ」）。`ゲーム`・`時間`（1〜180分、省略で30分）・`上乗せ率`（1〜300％、省略で50）・`サーバー`（空なら許可されている全サーバー）を指定します。開始と終了は告知チャンネルに出ます。定例の突発イベントとは**重ならず、大きいほうだけ**かかります。1回の上乗せの上限（10,000ペリカ）は同じです。開催中に新しく開くと置き換わり、`終了` ですぐ終わらせられます |
| `/運営 パチンコ統計` | パチンコの当たり率・スタート入賞・還元率・最大連チャンを、設計した数字（予告の色・リーチの格ごとも）と実際の記録で並べて見ます。`サーバー`・`日数` で絞れます。回転数が少ないうちは「参考」と出ます。数字の調整は `games/pachinko.py` の表で行います |
| `/運営 還元率 設定` `一覧` | ゲームごとの還元率レベル（1〜6）の変更。詳しくは「還元率のレベル」の節 |
| `/運営 抽選 開催` `再掲示` `中止` | 指定したサーバーの**告知チャンネル**（ランキング掲示のチャンネル、無ければシステムチャンネル）に、抽選の募集を出す・出し直す・中止して返金する |
| `/運営 クイズ 追加` `一覧` `削除` | クイズの登録（入力フォームが開く）・一覧・削除 |
| `/運営 サーバー一覧` `サーバー許可` `サーバー取消` | Bot を使えるサーバーの管理 |
| `/ペリカ ランキング掲示` | ランキング掲示板の設置。サーバー内で、サーバー管理の権限を持つ人も使えます |

サーバーの端末から行う `manage.py` も、そのまま使えます（Bot の起動中でも安全です）。

```bash
uv run manage.py grant サーバーID ユーザーID 金額 [理由]   # ペリカを付与（1〜10,000,000）
uv run manage.py servers                               # サーバーの許可状況
```
※ pip / venv 環境の場合は `uv run` を `.venv/bin/python` に置き換えてください。
